# 2026-04-09 变更摘要

## 小布对话历史：客户端缓存与预取

**背景**：每次打开对话浮层都会清空列表并调用 `fetchChatMessagesAction`，体感偏慢。

**改动**：逻辑集中在 **`components/features/chat/useChatHistoryLoader.ts`**（`useChatHistoryLoader`），`FloatingChatBot.tsx` 只负责编排对话与 UI。

**行为**（`useChatHistoryLoader`）：

1. **内存缓存**：`historyCacheRef` 保存最近一次成功拉取的消息列表（最多 300 条，与 `app/actions/chat-history` 的 `CHAT_FETCH_LIMIT` 对齐）。
2. **Stale-while-revalidate**：若已有缓存，打开浮层时**立即**展示缓存内容（不再先清空再转圈），同时在后台仍发起同一次拉取以与数据库对齐。
3. **并发去重**：`historyInflightRef` 合并同时进行的多处请求（例如预取与首次打开），避免重复打 Supabase。
4. **空闲预取**：`mounted` 后通过 `requestIdleCallback`（无则 `setTimeout`）在空闲时预取历史，用户首次点小布前数据往往已就绪。
5. **写后更新缓存**：`persistChatExchangeAction` 成功后调用 `pushExchangeToCache`，减少关闭再打开时的陈旧感。

**说明**：缓存随页面刷新清空；换家庭需整页导航后自然失效。首页等业务页的加载速度仍主要取决于 RSC 上的 `fetchMembers` / `fetchTransactions` 等，与本次对话优化无关。

## Tab 切换：服务端 household 缓存 + 客户端路由预取

**背景**：底部 Tab 切换时每个页面都是动态 RSC，此前**每次导航**都会再打 Supabase `households` 表把 Cookie 中的编码解析为 `household_id`（与成员/流水的 `unstable_cache` 不同步）。

**改动**：

1. **`app/actions/ledger.ts`**：`requireHouseholdId` 内对「规范化后的家庭编码 → `household_id`」使用 **`unstable_cache`**（`revalidate: 120`，标签 **`ledger`**），与 `fetchMembers` / `fetchTransactions` 一并随 `revalidateTag("ledger", "max")` 失效。
2. **`components/common/usePrefetchAppTabs.ts`** + **`MobileShell`**：在非 `/login` 路由下，用 **`requestIdleCallback`**（或短延迟 `setTimeout`）对 `/`、`/record`、`/stats`、`/members` 调用 **`router.prefetch`**，提前拉取各 Tab 的 RSC payload（与 `Link` 自带预取互补，覆盖进入应用后尚未 hover 的条目）。

3. **`next.config.ts`**：**`experimental.staleTimes.dynamic`** 设为 **120**（秒）。Next 默认对动态路由的客户端缓存为 **0**，切 Tab 会反复请求 RSC，体感像「整页重载」；拉长后可在短时间内复用已预取的 Flight（仍非浏览器层面的多页 DOM 常驻，见下）。

## 小布结构化对话：以数据库为准、弱化历史里的旧数字

**背景**：`chat_messages` 里的历史 assistant 回复可能带过时汇总；用户在 App 里改账、删账后，模型仍易沿用旧对话中的金额。

**改动**：

1. **`app/actions/mistral-chat.ts`** + **`lib/ledger/monthly-digest.ts`**：每轮 **`mistralLedgerChatAction`** 与 **`fetchTransactions` / `fetchMembers` 并行**拉数，用 **`computeMonthlyLedgerDigest`**（与 **`buildMonthlyLedgerDigest`** 同源逻辑；纯函数放在 lib，避免 `"use server"` 文件导出非 async 报错）生成本月摘要，并在系统提示末尾追加 **【本轮账本事实】** 说明：统计类回答**仅可引用该块**，聊天历史中的数字视为可能过期；无流水时不得编造；非本月问题若块中无数据则如实说明。
2. **`lib/llm/chat-ledger.ts`**：**`buildLedgerChatSystemPrompt`** 补充与上述一致的可信度规则；**intent=ready** 强调针对**当前这一笔**，勿把历史 assistant 里的金额当本条；统计无数据时 **intent=none**。
3. **`mistralChatAction`** 的 **`ASSISTANT_SYSTEM`** 同步强化「有事实块以事实块为准、无数据不编」的表述（保留接口备用）。

**说明**：本月小结仍走 **`generateMonthlySummaryAction`**，摘要来源不变；结构化对话每轮多一次与小结同口径的 DB 读，与单次对话原有成本相比可接受。

**补充（同日）**：**`fetchLedgerSnapshotData`**（`ledger.ts`）让小布与小结**直连读库、不走** `fetchTransactions` / `fetchMembers` 的 **`unstable_cache`**，避免改账后仍命中旧缓存。本月摘要从系统提示长块改为**紧贴当前 user 消息**注入，并把 **`mistralLedgerChatAction`** 的 **`temperature`** 降到 **`0.2`**，减轻捏造与采信历史气泡。

## 统计页图表：Recharts `width/height -1` 控制台告警

**背景**：`/stats` 下 **`ResponsiveContainer`** 使用 **`height="100%"`** 时，在部分布局阶段父级尚未测出有效尺寸，Recharts 会反复打出 **`The width(-1) and height(-1) of chart should be greater than 0`**。

**改动**：**`components/features/stats/StatsCharts.tsx`** 中三处图表改为 **`height={224}`**（与 **`h-56`** 一致）、**`minWidth={0}`**，外层增加 **`min-w-0`**；成员柱状图将 **`pt-2`** 与固定高度区域拆开，避免 padding 挤压测量。


## 小布结构化记账：提示词（分类默认「其他」、不二次确认）

- **`lib/llm/chat-ledger.ts`** · **`buildLedgerChatSystemPrompt`**：`missing` **禁止**含 `category`；不因分类不确定进入 **`collect`**；分类对不上列表时直接 **`ready`** 填「其他」并把描述写入 **`note`**。用户表达记账意图且金额/类型/记账人已可定时 **直接 `ready`**，**禁止**在 **`reply`** 里要求「确认再记」「要不要帮你记」等才入账。缺记账人时的追问仍保留（属缺槽补齐，非入账前确认）。
- **补充（收/支与分类自动识别）**：提示词要求模型从用户话术**自动**判断 **`type`**（支出/收入，附常见用语对照），**自动**将场景映射到分类白名单；**不要**追问「收入还是支出」；**仅**在完全无法判断收/支时把 **`type`** 列入 **`missing`**。分类仍对不上则用「其他」。
- **`docs/api.md`**、**`docs/development-guide.md`**、根目录 **`README.md`**：与上述行为对齐说明。
