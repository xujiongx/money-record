# 产品需求文档（PRD）

> 产品：家庭记账 · 版本：v1.1 · 状态：已实现 · 更新日期：2026-04-02

## 1. 文档信息

| 项目 | 内容 |
|------|------|
| 产品名称 | 家庭记账（温暖小账本） |
| 技术形态 | Next.js 移动端视口 + Supabase（PostgreSQL） |
| 多家庭 | 以 **6 位数字家庭编码** 区分数据；登录页可 **加入已有家庭** 或 **创建新家** |

## 2. 背景与目标

### 2.1 背景

家庭日常收支分散、难以及时对齐；需要一款**多人共用**、**数据云端一致**、**以手机为主**的轻量账本，并支持多个家庭相互隔离。

### 2.2 目标

- 进入应用前通过 **家庭编码** 识别当前家庭；支持 **创建新家庭**（名称 + 编码）并默认生成成员 **布布**、**一二**。  
- 展示家庭总收入、总支出与结余；最近账单与成员维度统计。  
- 快速记账（收入/支出、分类、记录人、备注）与图表统计。  
- UI 温暖友好（橙粉渐变、圆角、动效）；多设备通过 **定时轮询** 接近实时（非毫秒级推送）。

### 2.3 非目标（本期不做）

- 桌面端多栏布局、复杂预算与账单导入导出。  
- 完整账号体系（手机号/邮箱登录与密码找回）；家庭编码即当前「家庭口令」。  
- 独立开放 REST 对外 API。  
- 公开环境下的创建家庭风控（频率限制、审核）——可后续迭代。

## 3. 用户与场景

### 3.1 目标用户

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 家庭成员 | 如布布、一二（可新建家庭时自动创建） | 随时记账、看汇总、看对方记的账 |
| 家庭管理员 | 创建新家的用户 | 自定家庭名称与 6 位编码，立即开始使用 |

### 3.2 用户故事

1. 作为**用户**，我希望**用 6 位数字编码进入我的家庭账本**，以便**与他人共用同一套数据**。  
2. 作为**新用户**，我希望**在登录页创建家庭并自动有布布与一二两个记录人**，以便**不用先跑 SQL**。  
3. 作为**家庭成员**，我希望**打开首页就看到总收支和结余**，以便**快速了解家庭财务状况**。  
4. 作为**记账人**，我希望**选收入/支出、分类和记录人一键保存**，以便**几秒记完一笔**。  
5. 作为**用户**，我希望**在另一台设备记账后，本机过几秒能看到更新**，以便**少手动刷新**（依赖轮询间隔）。

## 4. 功能需求

| 编号 | 模块 | 需求描述 | 优先级 | 验收要点 |
|------|------|----------|--------|----------|
| F-00 | 访问控制 | 无有效家庭会话时中间件跳转 `/login` | P0 | Cookie 为合法 6 位数字方可进首页等 |
| F-00a | 登录 | 输入 6 位编码加入已有家庭 | P0 | 编码在库中存在则进入 |
| F-00b | 创建新家 | 输入家庭名称 + 6 位编码；创建家庭并插入成员布布、一二 | P0 | 编码唯一；成功后自动登录 |
| F-00c | 切换家庭 | 成员页清除会话并回登录页 | P1 | Cookie 与 localStorage 编码清除 |
| F-01 | 仪表盘 | 总收入、总支出、结余卡片 | P0 | 与当前家庭流水汇总一致 |
| F-02 | 仪表盘 | 最近账单列表（时间倒序） | P0 | 展示分类、金额、记录人、时间 |
| F-03 | 仪表盘 | 成员头像墙 + 每人笔数与收支配比 | P0 | 与当前家庭成员流水一致 |
| F-04 | 记账 | 收入/支出切换、金额、分类、记录人、备注 | P0 | 写入当前 `household_id` |
| F-05 | 分类 | 支出/收入分类与代码常量一致 | P0 | 见 `lib/categories.ts` |
| F-06 | 成员 | 列表、每人统计、最近流水摘要 | P0 | 仅当前家庭 |
| F-07 | 统计 | 支出饼图、收入饼图、成员支出柱图；**日/周/月/年**维度（默认**当月**），**前后切换**时间段，**回到今天**重置锚点；按记账时间筛选 | P0 | 切换维度三图同步；无数据空态 |
| F-08 | 同步 | 首页与统计页定时拉取流水 | P0 | 间隔约 4～5 秒级 |
| F-09 | 删除 | 删除单条流水（确认） | P1 | 仅当前家庭数据 |
| F-10 | UI | 移动端视口、橙粉渐变、圆角、动效 | P0 | 窄屏可用 |

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | MVP 数据量下首屏与操作流畅 |
| 安全 | **Service Role 仅服务端**；当前 **无 anon 读业务表策略**；家庭编码等同口令，勿泄露；创建家庭为公开能力，生产需评估风控 |
| 可用性 | 配置错误时有明确提示（SetupPrompt）；登录/创建错误有文案反馈 |

## 6. 里程碑

| 阶段 | 交付 |
|------|------|
| v1.1 | 多家庭编码、中间件、登录/创建新家、轮询同步、文档同步 |

## 7. 风险与待决

| 项 | 说明 |
|----|------|
| 公开部署 | 任意访客可创建家庭，可能被刷库；可后续加验证码/审核/关闭注册 |
| 家庭编码泄露 | 获知编码即可通过服务端接口访问该家庭数据（Cookie 会话） |
