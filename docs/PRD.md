# 产品需求文档（PRD）

> 产品：家庭记账 · 版本：v1.2 · 状态：v1.1 已实现 / **Budget v1 已落地**（分类预算等见规划） · 更新日期：2026-11-16

## 1. 文档信息

| 项目 | 内容 |
|------|------|
| 产品名称 | 家庭记账（温暖小账本） |
| 技术形态 | Next.js 移动端视口 + Supabase（PostgreSQL） |
| 多家庭 | 以 **6 位数字家庭编码** 区分数据；登录页可 **加入已有家庭** 或 **创建新家** |

## 2. 背景与目标

### 2.1 背景

家庭日常收支分散、难以及时对齐；需要一款**多人共用**、**数据云端一致**、**以手机为主**的轻量账本，并支持多个家庭相互隔离。记账之外，布布与一二还希望「这个月还能花多少」有一个共同数字，避免月底才发现超支。

### 2.2 目标

- 进入应用前通过 **家庭编码** 识别当前家庭；支持 **创建新家庭**（名称 + 编码）并默认生成成员 **布布**、**一二**。  
- 展示家庭总收入、总支出与结余；最近账单与成员维度统计。  
- 快速记账（收入/支出、分类、记录人、备注）与图表统计。  
- UI 温暖友好（家用账本纸感：纸底细线、黏土橙实色、衬线标题）；多设备数据以 **进入页面 / 路由切换** 从服务端载入；**无定时轮询**；服务端对成员/流水读接口使用短期数据缓存（标签失效 + 写操作即时失效），非毫秒级推送。  
- **（规划）** 支持家庭级**月度支出预算**与可选**分类预算**，在首页 / 统计一眼看到「已花 vs 预算」。

### 2.3 非目标（本期 / 预算一期不做）

- 桌面端多栏布局、账单导入导出、银行同步。  
- 完整账号体系（手机号/邮箱登录与密码找回）；家庭编码即当前「家庭口令」。  
- 独立开放 REST 对外 API。  
- 公开环境下的创建家庭风控（频率限制、审核）——可后续迭代。  
- **大事记账预算 / 项目额度**（大事模块保持合计与分析即可，不挂预算）。  
- **复杂预算体系**：零基预算、多币种、信封滚动结转、成员个人私房预算隔离、收入预算编排、强制超支拦截（一期仅提示，不禁止记账）。

## 3. 用户与场景

### 3.1 目标用户

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 家庭成员 | 如布布、一二（可新建家庭时自动创建） | 随时记账、看汇总、看对方记的账、看本月预算还剩多少 |
| 家庭管理员 | 创建新家的用户 | 自定家庭名称与 6 位编码，立即开始使用；设定本月能花多少 |

### 3.2 用户故事

1. 作为**用户**，我希望**用 6 位数字编码进入我的家庭账本**，以便**与他人共用同一套数据**。  
2. 作为**新用户**，我希望**在登录页创建家庭并自动有布布与一二两个记录人**，以便**不用先跑 SQL**。  
3. 作为**家庭成员**，我希望**打开首页就看到总收支和结余**，以便**快速了解家庭财务状况**。  
4. 作为**记账人**，我希望**选收入/支出、分类和记录人一键保存**，以便**几秒记完一笔**。  
5. 作为**用户**，我希望**在另一台设备记账后，本机再次进入页面或切换 Tab 能看到更新**，以便**与云端一致**（依赖导航刷新与缓存失效；不保证秒级自动同步）。  
6. 作为**家庭成员**，我希望**为这个月设一个全家支出预算**，以便**布布和一二对「还能花多少」有共同预期**。  
7. 作为**用户**，我希望**在首页看到本月已花相对预算的进度**，以便**不用进设置才知道有没有超**。  
8. 作为**用户**，我希望**给餐饮、购物等分类单独设额度**（可选），以便**总预算够但某一类爆了也能看见**。

| F-10 | UI | 移动端视口、家用账本纸感、适度圆角、克制动效 | P0 | 窄屏可用 |

## 5. 产品规划：预算（Budget）

> 状态：**Budget v1 已实现**（月度全家总预算 + 首页/统计进度 + `/tools/budget`）；v1.1+ 仍为规划。对齐日常流水 `transactions`。**不含大事记账预算。**

### 5.1 问题与价值

| 现状 | 缺口 | 预算要解决的事 |
|------|------|----------------|
| 首页有「本月已花」、统计有图表 | 没有「计划花多少」 | 给全家一个共同的月度支出上限 |
| 分类可配置 | 分类只有事后占比 | 可选：某一类设额度，超了有提示 |

### 5.2 范围分期

```text
Budget v1（P0）— 月度全家总预算
  设置本月支出上限
  首页 / 统计展示：已花 / 预算 / 剩余（或超支）
  达 80% 轻提示；≥100% 超支强调（不拦截记账）

Budget v1.1（P1）— 分类预算
  对支出分类设可选额度（未设 = 不考核该类）
  统计页分类进度列表；与总预算并存（分类之和可不等于总预算）

Budget v2（P2）— 助手与体验
  小布「本月小结」带上预算进度
  跨月复制上月预算一键套用
  （不做）大事预算、强制拦账、私房预算、多币种、自动结转
```

### 5.3 规划功能表

| 编号 | 模块 | 需求描述 | 优先级 | 验收要点 |
|------|------|----------|--------|----------|
| B-01 | 总预算设置 | 当前家庭可设置**自然月**支出总预算（金额 > 0）；可改、可清空（清空=本月不启用） | P0 | 仅当前 `household_id`；按月键 `YYYY-MM` 隔离 |
| B-02 | 进度计算 | 「已花」= 该月 `transactions` 中 `type=expense` 且 `occurred_at` 落在该月的合计；**不含**大事支出 | P0 | 与首页「本月已花」口径一致 |
| B-03 | 首页展示 | 启用预算时，KPI 区展示进度条或「已花 / 预算」；超支用支出色强调 | P0 | 未设置预算时 UI 与现网一致（可有「设个预算」轻入口） |
| B-04 | 统计页 | 月维度下展示预算进度；切换到非月维度可隐藏或提示「预算按月」 | P0 | 与 F-07 时间锚点一致 |
| B-05 | 阈值 | 已花 ≥ 预算×80% 且未超：轻提示文案；已花 ≥ 预算：超支文案 | P1 | 不弹窗打断记账 |
| B-06 | 分类预算 | 可为支出分类设置月额度；列表展示已花/额度/剩余 | P1 | 分类删除后额度失效或归「其他」策略写进实现说明 |
| B-07 | 入口 | 成员「更多功能」或设置中增加「预算」；统计页可快捷改本月预算 | P0 | 移动端一屏完成设置 |
| B-08 | 小布 | 本月小结事实块附带预算进度（若已设置） | P2 | 无预算时行为不变 |
| B-09 | 套用上月 | 一键把上月总预算（及可选分类预算）复制到本月 | P2 | 不覆盖用户已手改的本月值（或二次确认） |

### 5.4 信息架构（规划）

```text
MobileShell
  Home
    KPI「本月已花」
+     BudgetProgress?          # 有月预算才显示
  Stats
    月维度摘要
+     BudgetProgress
+     CategoryBudgetList?      # v1.1
  Members → 更多功能
+   /tools/budget              # 设置本月总预算 / 分类预算
```

### 5.5 数据模型草案（实现时再落迁移）

```text
households
  └── budgets
        household_id
        period_type = 'month'
        period_key  = 'YYYY-MM'
        scope       = 'household' | 'category'
        category    = text?          # scope=category 时对应支出分类名
        amount      = numeric(14,2)  # > 0
        unique (household_id, period_type, period_key, scope, category)
```

- 读写走现有 Server Actions + `household` Cookie 边界；缓存标签建议独立 `budgets`（或挂在 `ledger` 上，写预算时 `revalidateTag`）。  
- **不改动** `major_events` / 大事相关表与缓存。

### 5.6 交互原则

- **全家共用一套预算**（不按成员拆私房）。  
- **只约束日常支出**；收入与大事支出不进预算进度。  
- **提示不拦截**：超预算仍可记账（与「轻量账本」一致）。  
- **口径透明**：预算「已花」只算 `transactions` 支出，与首页「本月已花」一致。  
- **视觉**：进度与现有暖橙 / 支出红 token 一致，避免另起一套「理财 App」风格。

### 5.7 验收场景（Budget v1）

1. 未设预算：首页与现网一致；设置页可进入并保存金额。  
2. 设本月预算 3000，记两笔日常支出合计 900：进度约 30%，剩余 2100。  
3. 已花到 2400（80%）：出现接近上限提示。  
4. 已花到 3100：超支展示；仍可再记一笔。  
5. 进入下月：默认无预算（或仅提供「套用上月」入口，v2）；上月进度不串月。  
6. 同月大事花了 5000、日常花了 1000、总预算 3000：日常预算进度只认 1000（大事不计预算）。

## 6. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | MVP 数据量下首屏与操作流畅；统计页 **Recharts 按需分包**；全局与 `/stats` **分段 Loading** 改善 Tab 切换感知；预算进度与流水聚合同请求或可缓存，避免额外瀑布 |
| 安全 | **Service Role 仅服务端**；当前 **无 anon 读业务表策略**；家庭编码等同口令，勿泄露；创建家庭为公开能力，生产需评估风控 |
| 可用性 | 配置错误时有明确提示（SetupPrompt）；登录/创建错误有文案反馈；预算未设置时不制造空状态焦虑 |

## 8. 风险与待决

| 项 | 说明 |
|----|------|
| 公开部署 | 任意访客可创建家庭，可能被刷库；可后续加验证码/审核/关闭注册 |
| 家庭编码泄露 | 获知编码即可通过服务端接口访问该家庭数据（Cookie 会话） |
| 分类改名 | 分类预算以分类名为键时，改名会导致额度失联；实现期需决定「按 id」还是「改名迁移」 |
| 总预算 vs 分类和 | 分类额度之和可以大于或小于总预算；产品文案需说明「分类是局部提醒，总预算是全家天花板」 |
| 时区 | `occurred_at` 与「自然月」边界需与现有「本月已花」一致（避免预算月与 KPI 月错位） |
